CURRENT GOOGLE SHEETS LAYOUT / HEADERS
========================================
Source: core/google_sheets.py (SUMMARY_HEADERS / TRANSACTIONS_HEADERS
constants). Single source of truth is core/google_sheets.py. Synced rows
are appended positionally - order here MUST match the append code in
_append_summary / _append_transactions.

SHEET 1: "Shift Summary"  (27 columns, one row per shift)
----------------------------------------------------------
 1  Shift ID
 2  Date
 3  Day
 4  Shift Timing
 5  Employee Name
 6  Topup Sale
 7  Morning Pkg Sale
 8  Nighter Pkg Sale
 9  PS5 Sale
10  Cafeteria Sale
11  Total                    = grand_total (gross; expenses NOT subtracted)
12  Online Payments
13  Cash Received
14  Actual POS Amount
15  Total Payment Received   = cash + online + pos (computed)
16  Total Expenses           = Detailed multiline list of expenses + Total (or 0 if none)
17  Reconciliation           = Total - Total Payment - Total Expenses (computed)
18  Grand Total              = Total - Total Expenses (net; computed)
19  Total TAX Amount
20  Morning Pkg Count
21  Nighter Pkg Count
22  PS5 Session Count
23  Inventory
24  Closed At
25  Pancafe Screenshot
26  Form Screenshot
27  Note

Row values appended (in order):
shift_id, date, day, shift_timing, employee_name, topup_sale,
morning_pkg_total, nighter_pkg_total, ps5_total, cafeteria_sale,
total_sale, online_payments, cash_received, actual_pos_amount,
total_payment, exp_str, reconciliation, grand_total_net,
total_tax_amount, len(morning_packages), len(nighter_packages),
len(ps5_sessions), inv_str, closed_at, pancafe_url, form_url, note_str

Column 27 "Note" is free text and carries NO amount:
  0 notes -> "-"
  1 note  -> the text on its own
  2+      -> numbered, one per line ("1. ...\n2. ...")
Notes never contribute to Total Expenses (16), Reconciliation (17) or
Grand Total (18) - they are not expenses.

SCREENSHOT URL PERSISTENCE (ImgBB rate-limit safety)
-----------------------------------------------------
- ShiftData stores pancafe_screenshot_url / form_screenshot_url locally so
  regular syncs upload a screenshot to ImgBB at most once and reuse the
  stored URL. The forced Re-upload endpoint replaces those stored URLs with
  freshly hosted links on success; failures leave both the cell and the
  stored URL untouched.
- _append_summary() calls _resolve_screenshot_url() which returns (url,
  changed); a changed flag triggers save_shift so future re-syncs skip ImgBB.

NOTES
-------
- There is intentionally NO clear/wipe endpoint: shift data is append-only.
  Deleting worksheet tabs manually recreates them empty on the next sync
  (only unsynced closed shifts re-append).
- Summary sheet created with cols=len(SUMMARY_HEADERS); transactions sheet
  with cols=len(TRANSACTIONS_HEADERS)+1 (one trailing spare column).
- Column 11 "Total" == stored grand_total (gross). Column 18 "Grand Total"
  == net = grand_total - total_expenses. Reconciliation ~ 0 by design.
- Fallback positional deps: sync-all dedup uses row[0]|row[3]|row[10]
  (Date|Employee|Total) ONLY on legacy sheets without a "Shift ID" column;
  new-layout sheets always dedup by Shift ID (col A). Transaction dedup
  fallback indices Employee=3, Timestamp=13. Re-upload fallback cols 23/24.
- SCHEMA MIGRATION: _ensure_sheets_exist() calls _topup_headers(), which
  appends any header missing from the END of the sheet's own header row
  (e.g. adding "Note" to a 26-column sheet). It never reorders
  or rewrites existing headers, and it writes NOTHING if the live headers
  are not an exact prefix of the expected layout - a drifted or hand-edited
  sheet must be fixed deliberately. Safe to run on every sync.
- GRID WIDTH: _topup_headers() widens the grid with ws.resize() before writing
  the new header. This is required because append_row()/append_rows() DO
  auto-widen the grid ("widens the worksheet if there are more values than
  columns") but cell().value does NOT - writing past the current column count
  fails with [400]: Range ('Shift Summary'!AA1) exceeds grid limits. Max
  columns: 26. The resize is guarded by col_count < len(expected), so it can
  only ever widen (never shrink, so no cell data is lost) and it happens at
  most once per sheet.
